# Tail 첫 버전 요구사항

CS 개념과 이력서에 적은 경험을 자기 말로 설명하고, 답변에 연결되는 꼬리 질문으로 이해의 빈틈을 찾는 개인용 macOS 앱을 만든다. 학습 기록은 다시 답해보는 복습으로 이어진다.

2026-10-12 사용자 선택과 개발 승인을 반영한다. 첫 버전 기능과 기술 선택은 확정했다. 개발 중 표시 이름은 Tail이며 최종 이름은 추후 정한다.

## 확정된 요구사항

| 항목 | 동작 |
|---|---|
| 플랫폼 | macOS 앱으로 제공한다. |
| 학습 입력 | 사용자가 공부할 CS 주제나 질문할 경험을 입력한다. |
| 경험 활용 | 첫 버전은 이력서나 프로젝트 경험을 텍스트로 붙여넣어 질문에 반영한다. |
| 질문 생성 | 입력한 주제로 질문을 생성하고, 실제 답변을 바탕으로 꼬리 질문을 이어간다. |
| 답변 입력 | 직접 입력하거나 외부에서 전사한 텍스트를 붙여넣는다. 녹음과 전사는 사용자가 별도 도구로 처리한다. |
| 피드백 | 매 답변을 제출한 뒤 피드백을 보여준다. |
| 참고 답안 | 각 질문에 참고 답안을 제공하고, 사용자가 눌렀을 때 펼친다. |
| 학습 기록 | 질문, 답변, 피드백, 참고 답안과 질문 사이의 연결을 보관한다. |
| 복습 | 저장된 학습 기록을 활용해 다시 공부할 수 있어야 한다. |
| AI 연결 | 배우자와 같은 기존 Codex CLI 로그인 방식을 사용한다. |
| 참고 프로젝트 | 배우자의 디자인과 공통 개발 지침을 참고하고, 이 앱의 질문과 복습 흐름에 맞게 설계한다. |
| 진행 순서 | 요구사항을 정리한 뒤 구현에 들어간다. |

## 첫 버전의 학습 흐름

주제와 선택한 경험 입력 → 첫 질문 → 내 답변 → 피드백 → 필요한 경우 참고 답안 → 꼬리 질문 → 학습 마무리 → 이후 재답변.

1. 새 학습에서 주제를 입력한다. 프로젝트 경험은 선택 입력으로 두어, 경험이 없는 기본 CS 개념도 바로 공부할 수 있게 한다.
2. AI가 학습 범위를 짧게 보여주고 첫 질문 하나를 제시한다. 새 학습에서 소주제를 선택 입력해 넓은 범위를 좁힐 수 있다.
3. 사용자가 답변을 입력한다. 입력 중인 내용은 자동 저장하며, 제출 전에 전사 오류를 고칠 수 있다.
4. 제출한 답변에 대한 피드백과 다음 꼬리 질문을 준비한다. 참고 답안은 별도 펼치기 동작으로 확인한다.
5. 피드백을 읽고 같은 질문에 다시 답하거나, 꼬리 질문으로 넘어가거나, 학습을 마칠 수 있다.
6. 마무리 화면에서 헷갈린 개념과 다시 답할 질문을 확인한다. 복습 대상은 사용자가 추가하거나 제외할 수 있다.

한 세션은 처음 질문 하나와 꼬리 질문 최대 세 개를 기본으로 한다. 마무리 시점을 보여주되 사용자가 중간에 끝내거나 명시적으로 더 이어갈 수 있다. 질문 수와 시간은 통과 조건으로 사용하지 않는다.

## 질문 생성과 학습 범위

- 한 번에 답할 중심 질문을 하나씩 보여준다. 서로 독립적인 질문 여러 개를 한 문장에 묶지 않는다.
- 질문은 개념 설명, 동작 원리, 선택 이유, 단점과 대안, 실제 상황 적용을 다룬다. 모든 세션에서 이 순서를 강제하지 않는다.
- 답변에 오류가 있으면 해당 전제부터 확인한다. 충분히 설명했다면 다른 조건이나 반례로 이해를 확인한다.
- 경험을 입력한 경우 사용자가 한 일, 선택 이유와 검증 근거를 묻는다. 입력하지 않은 기여나 수치, 성과를 만들어내지 않는다.
- 경험에서 벗어난 가정 문제는 가정이라고 표시한다. 일반 CS 문제와 실제 경험에 대한 질문을 구분한다.
- DB 제품이나 버전에 따라 답이 달라지는 질문은 조건을 명시하거나 먼저 조건을 확인한다.
- 비슷한 질문을 의미 없이 반복하지 않는다. 주제 밖으로 확장할 때는 이유를 보여주고 사용자가 선택하게 한다.
- 질문이 불명확하면 사용자가 추가 설명을 요청할 수 있다. 답변을 시작하지 못할 때는 힌트나 `모르겠어요`를 선택할 수 있다.

예를 들어 채번 경험에서는 다음과 같은 흐름이 가능하다. 실제 꼬리 질문은 각 답변에 따라 달라진다.

> 첫 질문: 현재 최댓값에 1을 더해 번호를 발급하면 동시 요청에서 어떤 문제가 생길까요?
>
> 꼬리 질문: 두 요청이 같은 값을 읽는 순서를 설명해볼 수 있나요?
>
> 꼬리 질문: 트랜잭션으로 감싸는 것만으로 충분할까요? 어떤 조건을 확인해야 할까요?
>
> 경험 질문: 실제로 선택한 해결책과 그 방법이 적합했던 이유는 무엇인가요?

## 피드백과 참고 답안

피드백은 맞게 설명한 부분, 고칠 부분, 빠진 핵심 이유를 구분한다. 평가 근거가 되는 사용자 답변의 문장을 짧게 연결해 보여준다. 단순한 칭찬이나 근거 없는 점수만 제시하지 않는다.

| 판단 기준 | 확인할 내용 |
|---|---|
| 개념의 정확성 | 핵심 개념과 전제 조건을 올바르게 설명했는가 |
| 이유와 과정 | 왜 그런 결과가 생기는지 설명했는가 |
| 적용과 한계 | 해당 질문에서 필요한 사례, 예외나 대안을 설명했는가 |
| 경험의 근거 | 경험 질문에서 본인의 행동과 확인한 결과를 구분했는가 |

질문의 범위에 필요한 기준만 사용한다. 답변에 아직 나오지 않은 내용은 틀렸다고 단정하지 않고 확인할 부분으로 남긴다. 구어체, 군더더기나 사소한 전사 오류 때문에 개념 이해를 낮게 평가하지 않는다. 의미가 모호한 표현은 먼저 확인한다.

참고 답안은 다음 내용으로 구성한다.

- 핵심 키워드 세 개 안팎.
- 약 1분 동안 자기 말로 풀어 설명할 수 있는 답변 예시.
- 더 자세한 원리와 적용 조건, 필요한 경우 코드나 SQL 예시.
- 경험 질문에서는 제공된 사실만 사용한 답변 구조. 부족한 사실은 사용자가 채울 질문으로 남긴다.

참고 답안은 정답이 하나인 것처럼 취급하지 않는다. 타당한 다른 설명과 해결법도 인정한다. 기술적 사실을 확인하는 데 필요한 공식 문서나 원문 근거를 연결하고, 실제 확인하지 못한 URL이나 인용을 만들어내지 않는다. 확인이 필요한 설명에는 그 상태를 표시한다.

피드백은 제출 직후 공개한다. 참고 답안의 기본 공개 시점은 첫 답변 제출 이후이며, `모르겠어요`로 답안을 먼저 확인하는 경로도 제공한다. 이 경우와 힌트 사용 여부는 복습 판단을 위해 기록한다.

## 복습 기능

복습에서는 먼저 질문만 보여주고 이전 답변, 피드백과 참고 답안을 접어둔다. 다시 답한 뒤 이전 답변과 비교해 무엇이 보완됐는지 확인한다.

- `오늘 복습`에서 예정된 질문을 확인한다.
- 피드백의 보완점과 사용자의 선택으로 복습 질문을 만든다. 같은 질문은 복습 목록에 중복 등록하지 않는다.
- 복습은 원래 질문에 대한 재답변부터 지원한다. 상황을 바꾼 응용 질문은 이후 확장 후보로 둔다.
- 재답변 후 `다시 필요`, `조금 헷갈림`, `설명 가능`으로 스스로 평가한다.
- 초기 간격은 1일, 3일, 7일 같은 단순한 단계로 시작하고, 이해 상태에 따라 당기거나 늦추는 방식으로 한다. 이 수치를 최적의 학습 간격으로 주장하지 않는다.
- 미룬 복습을 강제로 몰아서 시키지 않고, 오늘 수행할 분량을 선택할 수 있게 한다.
- 참고 답안을 열어 읽었다는 이유만으로 복습을 완료 처리하지 않는다. 재답변이나 명시적인 상태 선택을 사용한다.
- AI의 판단과 사용자 자기평가를 구분해 보관한다. 사용자가 복습 일정과 대상을 직접 조정할 수 있다.

## 기록과 데이터 보존

학습 주제마다 여러 세션을 둘 수 있고, 각 세션에는 질문 순서와 부모 질문을 보관한다. 같은 질문에 다시 답해도 이전 답변을 덮어쓰지 않는다.

| 저장 단위 | 보관할 내용 |
|---|---|
| 학습 주제 | 제목, 학습 목적, 태그, 관련 경험 텍스트 |
| 학습 세션 | 사용한 경험의 당시 사본, 시작 시각, 진행 위치, 진행 중 또는 마무리 상태 |
| 질문 | 질문 본문, 부모 질문, 질문 의도와 조건 |
| 답변 시도 | 제출 시각, 원문, 피드백, 참고 답안, 힌트와 답안 공개 여부 |
| 복습 기록 | 연결된 질문, 재답변, 자기평가, 다음 복습일 |
| 생성 상태 | 생성 완료, 취소 또는 실패 상태와 재시도에 필요한 정보 |

자동 저장은 입력 초안과 제출된 답변 모두에 적용한다. 제출한 답변은 새 시도로 다시 작성하고 원본을 보존한다. 경험 텍스트를 수정해도 지난 세션이 사용한 내용은 달라지지 않는다.

저장 데이터는 로컬 SQLite를 사용한다. 저장된 기록 열람과 답변 초안 작성은 인터넷 없이 가능하게 하고, AI 생성과 새 피드백은 연결이 필요하다고 표시한다. 질문 생성에 필요한 주제와 선택한 경험, 답변은 원격 AI 처리에 전달된다.

주제와 질문, 답변 본문을 검색하고 복습 대상이나 태그로 좁혀볼 수 있게 한다. 기본 백업과 복원을 제공하고, 읽기용 Markdown 내보내기는 우선 확장 후보로 둔다. 삭제 범위는 사용자가 확인할 수 있게 표시한다.

## 화면과 디자인

기본 화면은 탐색 사이드바와 학습 본문 두 영역으로 구성한다. 사이드바에는 오늘 복습, 학습 주제, 학습 기록과 설정으로 가는 경로를 둔다. 학습 본문에는 현재 질문과 답변 입력을 가장 잘 보이게 배치한다.

이전 문답은 순서가 보이는 목록으로 접어둘 수 있게 한다. 답변 제출 뒤 피드백과 선택 공개 답안이 해당 답변에 붙는다. 좁은 창에서는 사이드바를 숨길 수 있고, 항상 넓은 세 열 화면을 요구하지 않는다.

- macOS 26 이상에서 SwiftUI와 필요한 AppKit으로 네이티브 창, 탐색, 메뉴와 입력 컨트롤을 구성하는 방향으로 구현한다.
- 시스템 글꼴과 의미적 색을 사용하고, 글자 크기와 밝게 또는 어둡게 보는 설정을 제공한다. 기본 18pt, 14~36pt 범위를 제공한다.
- 본문과 답변 입력의 가독성을 우선한다. Liquid Glass는 지원되는 시스템 탐색과 조작에 절제해서 적용한다.
- 새 학습, 답변 제출, 답안 보기, 마무리처럼 다음 행동을 이해할 수 있는 이름을 사용한다.
- 메뉴와 단축키로 주요 행동에 접근하게 한다. Enter는 줄바꿈으로 유지하고 제출은 명시적인 버튼이나 별도 단축키로 실행한다.
- 긴 붙여넣기, 한글 입력 조합, 코드 블록과 SQL, 작은 창, 큰 글자, 키보드 탐색, VoiceOver를 검증한다.
- 생성 중에는 현재 상태와 취소를 표시하고, 입력 초안과 이전 기록을 계속 확인할 수 있게 한다.

Apple의 Materials 지침은 Liquid Glass를 탐색과 조작을 위한 층으로 설명하며 본문에 남용하지 않도록 안내한다. 이 앱에서도 질문과 긴 답변에는 읽기 편한 본문 배경을 사용한다. [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials), 확인 2026-10-12.

## AI 연결과 오류 처리

기존 Codex CLI 로그인 방식은 확정사항이다. 공식 문서에 따르면 CLI는 ChatGPT 구독 인증을 지원하고, 비대화형 실행은 저장된 CLI 인증을 기본적으로 재사용한다. [OpenAI 인증 안내](https://learn.chatgpt.com/docs/auth), [비대화형 실행 안내](https://learn.chatgpt.com/docs/non-interactive-mode), 확인 2026-10-12.

- CLI 설치와 로그인 상태를 확인하고 설정 화면에서 문제 해결 경로를 제공한다. 앱이 인증정보를 복사하거나 전역 AI 설정을 바꾸지 않는다.
- 연결 실패, 로그인 만료, 사용 한도, 생성 취소와 응답 형식 오류를 구분한다. 실패 시 기존 기록과 입력을 보존한다.
- 사용자가 제출한 답변을 먼저 저장하고 AI 결과를 추가한다. 재시도는 동일한 제출에 연결하여 중복 문답을 만들지 않는다.
- 질문과 피드백, 참고 답안은 구조를 검증한 뒤 완료 상태로 저장한다. 형식 검증 성공과 내용의 정확성을 구분한다.
- 이미 만든 피드백과 답안을 열 때는 재생성하지 않는다. 새 생성과 재생성은 사용자의 행동에 연결한다.
- 학습 생성 작업에는 필요한 입력만 전달한다. 학습 자료의 문장을 도구 실행이나 파일 변경 지시로 취급하지 않는다.

Codex CLI를 격리된 작업 폴더에서 호출하고 기본 모델을 사용한다. 공식 자료 검색은 버전 차이, 불확실한 설명과 이의 제기 때 수행한다. SQLite 저장과 실행 계약은 상세설계에 기록한다. 추가 API 키나 유료 API로 자동 전환하는 기능은 포함하지 않는다.

## 첫 버전의 우선순위

| 우선순위 | 기능 |
|---|---|
| 필수 흐름 | 주제와 경험 입력, 한 질문씩 제시, 답변과 즉시 피드백, 선택 공개 답안, 답변에 따른 꼬리 질문 |
| 필수 보존 | 자동 저장과 재개, 답변 시도별 기록, 생성 취소와 실패 복구, 기본 백업과 복원 |
| 필수 복습 | 마무리 요약, 복습 대상 선택, 오늘 복습, 재답변과 이전 답변 비교, 단순 복습 간격 |
| 학습 보조 | 힌트와 모르겠어요, 질문 설명 요청, 태그와 검색, 피드백 오류 표시 |
| 다음 확장 | 상황을 바꾼 복습 질문, 주제별 반복 약점 요약, 경험 텍스트 보관함, Markdown 내보내기 |
| 이후 검토 | 면접 종료 후 일괄 피드백, 채용 공고별 연습, PDF 이력서 가져오기, 질문 연결을 시각화한 화면 |

첫 버전에는 앱 내 녹음과 자동 전사, 실시간 음성 면접, 클라우드 동기화, 이력서 편집기, 대규모 통계 대시보드를 넣지 않는 방향으로 구현한다. 현재 목표에는 텍스트 답변과 복습 흐름이 우선이다.

## 첫 버전의 완료 조건

1. CS 주제만 입력한 경우와 경험 텍스트를 함께 입력한 경우 모두 학습을 시작할 수 있다.
2. 서로 다른 답변을 제출하면 그 답변의 내용과 부족한 근거에 연결되는 꼬리 질문이 나온다.
3. 매 제출 후 피드백을 보고, 참고 답안은 선택해서 펼칠 수 있다.
4. 경험 기반 참고 답안에 사용자가 제공하지 않은 성과나 수치를 만들어 넣지 않는다.
5. 앱을 종료하고 다시 열면 저장된 입력 초안과 진행 위치를 복구한다.
6. AI 실패와 취소 후에도 제출 답변을 유지하고, 재시도로 같은 답변이 중복 생성되지 않는다.
7. 학습을 중간에 마무리할 수 있고, 복습할 질문을 선택할 수 있다.
8. 복습 시작 시 과거 답안을 숨기고, 재답변 뒤 이전 시도와 비교할 수 있다.
9. 참고 답안 열람만으로 학습 또는 복습을 완료 처리하지 않는다.
10. 백업을 복원하면 질문 연결, 답변 이력과 복습 상태가 함께 복구된다.
11. 작은 창과 큰 글자에서도 현재 질문, 답변 입력과 주요 버튼이 가려지지 않는다.
12. 고정된 예제 데이터 검증과 실제 Codex 생성 검증을 구분하고 결과를 기록한다.

## 참고 프로젝트에서 이어갈 개발 원칙

배우자의 `AGENTS.md`, `docs/requirements.md`, `docs/design.md`, `docs/design-review.md`, `docs/agent-workflow.md`, 화면 코드와 저장된 퀴즈 화면을 참고했다.

- 공통 개발 지침, 제품 요구사항, 디자인, 상세설계와 실제 QA 기록의 역할을 구분한다.
- 제품 결정을 바꾸면 요구사항을 함께 갱신하고, 구현하지 않은 동작이나 검증하지 않은 결과를 완료로 기록하지 않는다.
- UI 변경은 해당 시점의 Apple 공식 지침과 실제 앱 실행 화면을 함께 확인한다.
- 사용자 변경과 Git 설정을 보존하고, 인증정보와 개인 학습 데이터를 소스 저장소에 넣지 않는다.
- 변경 범위에 맞는 자동 검사와 실제 동작 검증을 수행한다.

배우자의 앱 이름, 식별자, 데이터 경로, 교재 분량과 PDF 중심 기능은 해당 프로젝트의 결정이다. Tail은 별도 식별자와 저장 위치를 사용한다. 공통 개발 기준은 `AGENTS.md`, 검사와 패키징 명령은 `docs/development.md`에 둔다.

SwiftUI/AppKit, macOS 26 이상, SQLite 로컬 저장, 기존 Codex CLI ChatGPT 로그인으로 구현한다. 기본 네 문답과 1일, 3일, 7일 복습을 제공한다. 최종 앱 이름만 추후 결정한다.

## 앱 아이콘

배우자의 둥근 흰색 캐릭터와 빈 원형 눈, 작은 입을 참고한다. 사용자가 최종 선택한 첫 번째 빨간 머리띠 버전을 사용하고, 생각하는 손과 파란 질문 말풍선으로 Tail의 아이콘을 제작한다. 투명 전경과 배경을 분리하고 Icon Composer의 시스템 재질을 사용한다.
